# 右サイド広告・独自ドメインSEO移行設計

作成日: 2026-07-16  
対象: 助成金ナビ（`shienseido-navi.jp`）

## 1. 目的

ASP公式クリエイティブをPCの右側で視認できるようにしながら、旧Vercel URLから独自ドメインへの検索評価移行を完了させる。広い語句の「助成金」だけに依存せず、制度種別、地域、対象者、目的を軸にした検索入口を強化し、公式情報の確認先を持つ有用なページだけを検索エンジンへ送る。

## 2. 現状の根拠

確認日時: 2026-07-16（Asia/Tokyo）。公開URLはHTTP応答・生成HTML・sitemapを取得し、Search Consoleの数値は旧URLプレフィックスプロパティの画面、コンテンツ件数は`npm run audit:content`の出力で確認した。

- `https://shienseido-navi.jp/` はHTTPS、canonical、robots、sitemapが有効である。
- sitemapには独自ドメインの8,269 URLが含まれている。
- Search Consoleには旧URL `https://joseikin-navi-site.vercel.app/` だけが登録され、新ドメインは未登録である。
- 旧プロパティでは392ページがインデックス登録済み、5,342ページが未登録と表示されている。
- 旧Vercel URLは新ドメインをcanonicalとしているが、HTTP 200のままで恒久リダイレクトされていない。
- 公開HTMLにはSearch Consoleの所有権確認値が設定されていない。
- 現在のコンテンツ監査には説明不足1,197件、重複公式URL649件、重複タイトル203件が残っている。

## 3. 採用方式

「移行修復を最優先にし、PC右サイド広告と検索ハブ改善を同時に行う」方式を採用する。

### 広告配置

- 1024px以上では、本文を圧迫しない300〜320pxの右レールを設ける。
- トップでは検索フォームを左、A8.net公式300×250クリエイティブを右に置き、最初の画面内で見えるようにする。
- 一覧、制度種別、カテゴリ、都道府県、収益化可能な制度詳細では、右レールをヘッダー下で追従させる。
- 1023px以下では右レールを解除し、検索フォームまたは制度要約の直後へ1件だけ表示する。
- 広告表記は枠内の「PR」だけとし、スクリーンリーダー向け説明は残す。
- ASP公式クリエイティブ、公式リンク、計測ピクセルだけを使い、自作広告画像は使用しない。
- 公式クリエイティブを取得できない案件は表示しない。

### SEO移行

- 旧Vercelホストへのリクエストを、パスとクエリを維持して独自ドメインへ恒久リダイレクトする。
- `shienseido-navi.jp` をSearch Consoleへ追加し、所有権確認後にサイトマップを送信する。
- リダイレクト検査後、旧プロパティからアドレス変更を通知する。
- www、http、旧Vercel、独自ドメインの正規化を自動検査する。
- sitemapの`lastModified`は実際のコンテンツ更新日に基づかせ、ビルド時刻を全ページへ一律設定しない。
- 移行は2段階で行う。第1段階はホスト正規化、サイトマップ、index制御だけを反映し、旧サイトマップ全URLと主要URLを検査する。合格後に第2段階の広告・レイアウト・検索ハブ改善を反映する。
- 第1段階で転送ループ、転送先404、正規ドメインの誤転送、プレビューのindex許可が1件でも見つかった場合は第2段階へ進まない。Vercelの直前デプロイへ戻せる状態を維持する。

`lastModified`は、制度詳細では有効かつ未来でない`contentUpdatedAt`、`verifiedAt`、`publishedAt`の順、カテゴリ・都道府県・制度種別では掲載制度の有効な更新日の最大値を使う。静的ページは検証可能な更新日ソースがないため、推測値を出力しない。欠損・不正・未来日は省略する。

### 検索ページ設計

- 既存の`/support-type/grant/`を「助成金」の主ハブとして強化し、助成金の探し方、補助金等との違い、対象別・地域別入口を表示する。
- 補助金、給付金、貸付など各制度種別も、同じテンプレートへ実データに基づく件数、受付中、最近更新、地域別リンクを持たせる。
- 都道府県、カテゴリ、制度種別を相互にリンクし、詳細ページから3クリック以内で主要ハブへ戻れるようにする。
- クエリ付き検索結果は`noindex,follow`を維持し、薄い組合せページを新規生成しない。
- 公式URLなし、修正待ち、主要情報不足、重複ページはサイトマップから除外する。

## 4. 構造化データ

- WebSite、WebPage、CollectionPage、BreadcrumbList、Articleを、表示内容と一致する範囲で使用する。
- 公開画面に存在しないFAQをFAQPageとして出力しない。
- 運営者名が未設定ならOrganization、author、publisherを推測して出力しない。
- 詳細ページのArticle headlineは画面上の制度名と一致させる。
- 構造化データへ広告案件や確認できない評価を含めない。

## 5. 品質と計測

- 旧ホストのリダイレクト、canonical、robots、sitemap、noindex、構造化データを単体テストと生成HTML監査で確認する。
- 旧サイトマップに掲載された全URLについて、旧ホストから固定の正規オリジンへ301または308で1ホップ転送され、エンコード済みパス、クエリ、末尾スラッシュが保持されることを検査する。未知Host、転送ヘッダーの偽装、二重エンコード、転送先404、ループも拒否条件とする。
- 本番主要URLはindex可能、クエリ付き検索結果と実際のVercelプレビューURLはHTMLのrobotsと`X-Robots-Tag`の少なくとも一方でnoindexであることを実レスポンスで確認する。
- 320、390、768、1024、1440pxで横スクロールとコンテンツ被りがないことをE2Eで確認する。
- 右レール広告に公式画像、PR、`rel="sponsored nofollow noopener noreferrer"`、幅・高さ、計測属性があることを確認する。
- axeはトップ、一覧、カテゴリ、都道府県、制度種別、広告あり制度詳細、広告なし制度詳細をPC・モバイルで検査する。広告リンク名、代替テキスト、DOM重複、フォーカス順、200%ズーム、stickyによる遮蔽も確認する。
- Search Consoleでは新ドメインの所有権、サイトマップ受理、トップURLの検査結果を確認する。
- 順位は保証せず、インデックス数、表示回数、クリック数、検索クエリ、クロールエラーを継続指標とする。

## 6. 完了条件

- PCのトップ・主要一覧・対象制度詳細で、公式広告が右側に表示される。
- モバイルでは本文幅を維持したまま、適切な位置に広告が1件表示される。
- 旧Vercel URLが同一パスの独自ドメインへ恒久リダイレクトされる。
- 新ドメインがSearch Consoleで確認済みになり、サイトマップが送信される。
- 独自ドメインの主要URLがindex可能で、プレビュー環境はnoindexのままである。
- lint、typecheck、unit test、content audit、build、build audit、E2E、axeが通る。
