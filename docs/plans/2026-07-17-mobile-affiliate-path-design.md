# モバイル操作性・アフィリエイト導線強化設計

作成日: 2026-07-17  
対象: 支援制度ナビ（`shienseido-navi.jp`）

## 1. 目的

検索流入の中心であるモバイル利用者が、制度の重要情報と公式確認先を迷わず読める状態を維持しながら、提携済みで制度文脈と一致する民間サービスへ到達できる導線を作る。広告を固定フッターへ重ねず、本文を隠さず、公式CTAとPRを誤認させない。

## 2. 現状と原因

- PCの広告は検索フォームまたは制度本文の右レールへ表示される。
- 1023px以下では右レールが通常フローへ戻るが、制度詳細では`article`の後ろにあるため、広告は長いページの末尾まで到達しないと見えない。
- モバイル画面下には公式情報CTAが固定されている。ここへ広告を追加すると、公式リンクとの競合、本文遮蔽、誤タップが起きる。
- トップの公式バナー2件は縦積みになり、320〜390pxでは検索後の画面を大きく占有する。
- 公式300×250クリエイティブは固定寸法を前提にしており、320px画面の内側幅に合わせた縮小とタップ領域の扱いを明示する必要がある。

## 3. 採用方式

ユーザーが承認した「公式情報パネル直後にPRカードを置く」方式を採用する。

### 制度詳細

1. 制度要約
2. 公式情報パネルと公式CTA
3. 適合案件がある場合だけ独立したPR領域（モバイルは1件ずつ、最大2件）
4. 制度固有情報
5. 関連制度・訂正依頼

同じPR領域を1つだけSSRし、モバイルでは公式情報パネル直後、PCではCSS Gridで右レールへ配置する。PC用とモバイル用に同じ広告リンクを二重生成しない。切替点は制度詳細の既存2列レイアウトに合わせて1200pxへ統一し、1024〜1199pxでも記事末尾へ落ちない順序を維持する。

画面下の固定CTAは公式情報リンクだけを維持する。PRは固定せず、公式CTAと同じ青を使わない。

### トップ

検索フォームで「事業者・団体向け」を選んだ場合だけ「事業者向けPR」セクションを表示する。初期状態と個人・家族向け選択時は事業者広告を出さない。モバイルでは1件ずつ表示し、2件ある場合だけ「前の広告」「次の広告」ボタンと現在位置を表示する。横スワイプは使用しない。PCでは同じ広告DOMを既存右レール位置へ配置する。

## 4. コンポーネント設計

`AffiliateRecommendation`は広告主提供クリエイティブ、PR表記、計測属性、外部リンク属性を引き続き一元管理する。

新しい`ResponsiveAffiliatePlacement`は以下を担当する。

- `offers`と表示コンテキストを受け取る。
- モバイルでは1件ずつ、PCでは最大2件を縦に表示する。
- 2件ある場合だけ、モバイルへ44px以上の前後ボタン、現在位置、状態通知を出す。
- 各カードを`AffiliateRecommendation`へ委譲する。
- 広告が0件なら見出し、余白、枠を一切出さない。

案件選定ロジックや提携状態判定をUIコンポーネントへ重複させない。1ページ最大2件、同じ`offerId`は1回だけとする。一致案件が1件なら水増ししない。

制度詳細の選定はdefault-denyとし、禁止条件を許可条件より先に評価する。`primaryPurpose`だけでなく`grant.purposes`全件とセンシティブ分類・タグをOR判定し、医療、福祉、災害、生活困窮、障害、介護、ひとり親、葬祭、DV・虐待を1つでも含めば即0件にする。その後に`monetizationAllowed=true`、事業者系audience、index可能、公式確認先あり、受付中または受付前、案件のaudience・purpose・intent一致、blockedPurpose非該当をすべて必須にする。個人、noindex、closedも広告DOM、外部画像、計測を0にする。`placementMode: allGrantDetails`の迂回は廃止する。

並び順は、audience一致、purpose/intent一致、配置適性、priority、verifiedAtの決定的順序にする。選定不能理由は公開画面ではなく内部監査へ出す。

## 5. モバイルUX

- 320、375、390pxで横スクロールを本文全体へ発生させない。
- 320pxと400%相当でも、ページとPR領域に横スクロールを発生させない。
- 広告主提供クリエイティブは`width: min(300px, 100%)`相当で縮小し、正確なwidth/heightとaspect-ratioを必須にする。
- カード外枠と説明文はリンク化しない。広告主提供画像と明示CTAだけをリンクにし、CTAは44×44px以上、隣接操作は8px以上離す。
- 2件ある場合は`ul/li`、現在位置、前後ボタンを使い、タッチ・キーボード・スクリーンリーダーの全てで切り替えられるようにする。前後ボタンは各44×44px以上、ボタン間隔は8px以上とし、320/375/390pxの片手操作で誤タップ0件を確認する。
- フォーカスリング、自然なTab順、`prefers-reduced-motion`を維持する。非表示スライドはアクセシビリティツリーとTab順から除外する。
- 固定公式CTAは実測高さ56px以内、safe-area対応とする。本文側の`scroll-padding-bottom`と余白を実測高さに合わせ、200%/400%ズームでもフォーカスを隠さない。
- 代表的な長文詳細10ページで、公式CTAがPRより先に認識でき、最初のPRへ本文開始から2画面以内で到達できることを確認する。

## 6. 広告と公式情報の分離

- 公式CTAは青、PRは暖色系と「PR／広告」表記を維持する。
- PR領域は独立した`aside`とし、「制度の申請に必須ではない民間サービス」「広告主は制度実施機関ではありません」「申込みで当サイトが紹介料を受け取る場合があります」を表示する。
- 広告リンクに「申請する」「公式」「自治体への問い合わせ」は使わない。
- `rel="sponsored nofollow noopener noreferrer"`と新しいタブの説明を維持する。
- 自作クリエイティブは使用せず、ASPから取得し当サイトで確認した広告主提供クリエイティブだけを表示する。
- 未提携、リンク未取得、期限切れ、無効案件は表示しない。
- クリエイティブごとに取得元、確認日、遷移先host、表示期間、制度関連主張の確認状態を内部設定へ持たせる。期限切れ、host不一致、未確認claimは表示しない。
- 各広告リンクのアクセシブルネームは「{広告主}の{サービス名}を見る（PR、新しいタブ）」とし、画像内文字の冗長な読み上げを避ける。
- A8.netなど第三者への画像・計測通信はプライバシー設定と公開ポリシーへ連動し、未登録hostへの通信を禁止する。

## 7. 計測

描画と実視認を分離する。`affiliate_render`は描画、`affiliate_impression`はIntersectionObserverでカードの50%以上が1秒以上表示された場合だけ、同一ページ・offerId・placementにつき1回送る。クリックは外部遷移前にbeacon/keepalive相当で送信する。

- `home-business-selection`
- `grant-mobile-after-source`
- `home-hero`
- `grant-side-rail`

送信項目は`pageType`、`grantId`、`audience`、`purpose`、`offerId`、`network`、`placement`、`position`、`creativeId`、`format`、`deviceClass`、`experimentVariant`のみとし、個人情報を追加しない。画面外の広告、再レンダー、画面回転、戻る操作で重複送信しない。

主要指標はviewable CTR、案件別クリック、ASP成果数・EPCとする。ガードレールは`official_source_click`、`search_submit`、離脱、誤クリック兆候とし、公開後7日・28日で確認する。配置変更前の取得可能なベースラインも記録する。

## 8. テスト

- 単体: 0件、1件、2件、最大2件、同一ID重複なし、関連性順、公開不可・個人・センシティブ・closed・noindexの非表示。`primaryPurpose=businessGrowth`かつ副目的に各禁止purposeを含む混合fixtureも0件。
- 静的監査: PR／広告、広告主提供クリエイティブ、rel属性、計測属性、空枠なし、1 offer 1 DOM、許可hostだけの外部通信。
- E2E: 320、375、390、768、1023、1024、1199、1200、1440px、200%/400%ズーム、横溢れ、固定CTA遮蔽、表示順、キーボード操作。
- ブラウザ: トップ、長い事業者詳細、個人詳細、センシティブ詳細、広告画像404で画面とNetworkを確認する。許可設定外hostへの通信0、AnalyticsへのPII 0、片手操作10回で前後ボタンの誤タップ0を確認する。
- 計測: 画面外ではimpression 0、50%以上を1秒で1回、前後操作後の2件目だけ発火、再レンダー/回転で重複0。
- アクセシビリティ: axe critical/serious 0、全フォーカス矩形が固定CTAと非交差、VoiceOverで広告2件を識別可能。
- 性能: Slow 4G相当でLCP 2.5秒以内、CLS 0.1以内、INP 200ms以内、Performance 90以上を目標に変更前後比較する。広告画像はlazy、async decode、low priority、寸法予約を必須にし、広告をLCP要素にしない。
- 品質ゲート: lint、typecheck、unit test、affiliate audit、build、E2E、build audit。

## 9. 段階ごとの敵対レビュー

各段階の完了後に次の5視点で独立レビューする。

1. モバイル利用者: 読みやすさ、誤タップ、画面占有、到達速度。
2. 収益/CRO: 視認性、訴求順、クリック可能領域、計測欠落。
3. 行政情報の信頼性: 公式CTAとの誤認、センシティブ文脈、開示不足。
4. SEO/性能: LCP、CLS、DOM重複、内部リンク、モバイル評価。
5. アクセシビリティ/QA: キーボード、フォーカス、ランドマーク、横スクロール、320px。

重大・高優先の指摘はすべて修正する。中優先も合理的な範囲で解消し、見送る場合は理由を記録する。指摘解消後に同じ観点で再確認し、次段階へ進む。

## 10. 完了条件

- 適合する事業者向け制度詳細だけで、PRが公式情報パネル直後に表示される。
- 個人、センシティブ、closed、noindex、不適合ページでは広告DOM・外部画像・計測が0になる。
- PCでは右レール、モバイルでは本文内配置になり、同一offerのDOM・リンク・計測が1つだけになる。
- トップは事業者選択時だけPRを表示し、320pxと400%相当で横スクロールがない。
- 2件目は前後ボタン、キーボード、読み上げで到達でき、スワイプ誤遷移がない。
- 公式固定CTAがPRや本文を隠さない。
- PRと公式リンクを視覚・文言・セマンティクスで区別できる。
- 外部広告画像によるLCP/CLS悪化が性能予算内に収まる。
- 必須テストとビルドが通る。
